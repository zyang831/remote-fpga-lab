*Layout note.* Under 619 MB, `cma: Reserved 32 MiB at 0x00000000a9000000` sits inside the suspect `0xA8E80000–0xABFFFFFF` window; under `mem=768M` that region holds page cache, so equivalent writes would corrupt silently. "Clean at 768M" is therefore not evidence of safety. Fault addresses are IOVAs in the top of the 32-bit IOVA space (`0xffd…–0xffe…`), consistent with iommu-dma top-down allocation — so the failure is a missing/corrupt translation for dwc2, which fits either SMMU page-table corruption or stream-ID aliasing from a fabric master.

Real bug to chase: a dwc2 / uvcvideo / SMMU issue on this kernel (`6.12.11-gd7d192a9ddd9-dirty`) — F_TRANSLATION on dwc2's stream ID with IOVAs at the top of the 32-bit IOVA space (`0xffb8…–0xffe6…`, iommu-dma allocates top-down), i.e. dwc2 presenting an IOVA with no valid mapping. Candidates: use-after-unmap in dwc2's URB/DMA path aggravated by a second isochronous device, or uvcvideo buffer handling. Practical workaround for the demo and for camera bring-up: **unplug the USB webcam** (it is not needed — the demo path is MIPI). Next tests if it needs closing out: old bitstream + `mem=768M` + webcam over several boots to measure the fault rate; and the same with `CONFIG_USB_DWC2` debug or `iommu.passthrough=1` to confirm the layer at fault.

## Risks / unknowns (hardware-in-loop unless noted)

- D-PHY/CSI-2 after warm Linux fpga-region reconfig: reference only booted via u-boot `fpga load`.
- Camera ring vs `mem=768M`: Linux owns `0xAC00_0000–0xAFFF_FFFF` today; DMA scribbles kernel RAM without the base-dtb reservation. Demo `fdt_high` differs from reference (GUIDE §4.5).
- f2sdram sharing, now free-running by decision: 1080p60 ≈ 249 MB/s writes beside a DLA needing ~1.9 GB/s (estimate) on a 3.2 GB/s port. Sums fit on paper; contention unmeasured. Accepted fallback: halve sensor rate by doubling `FRM_LENGTH_LINES` (`0x0340/0x0341`, now `0x049C` = 1180 lines @ 60 fps in `imx519_modes.h:110`) → 30 fps, no new mode table; second option the Terasic `mode_1280x720_regs` table (`IMX519.cpp:675`). Hardware check: `cam_video` gap ≈ 33 ms.
- Camera accuracy unknown: 480×270 → 224² plain resize distorts aspect; fixed exposure/gain, no autofocus.
- Any camera-compatible arch is slower than `k32c16_sb12883` (5.62 fps); floor is Small at 4.33 fps. Optimizer output is an estimate (estimator +34 % optimistic on k32c16, −11 % pessimistic on Small) — only fit + board run settles it.
- Live rate bounded by ARM debayer (8.2 fps rgb888) and DLA (~4 fps): expect ~4 fps end to end plus ssh/Tailscale delivery.
- Board offline now; hardware gates pending.
